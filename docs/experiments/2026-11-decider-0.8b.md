# Experiment: decider-0.8b vs the Qwen3.5-0.8B baseline

This report records whether we should replace the copilot's model with
decider-0.8b, and the evidence for the decision. It is for the team and the
datathon judges. Laptop run, 2026-11-14, branch `exp/decider-0.8b`.

The task: pick the right letter (A–E) for multiple-choice maths problems from the
Kangaroo competition ([M3Kang](https://huggingface.co/datasets/qualcomm/M3Kang)), in
Catalan, English and Spanish. The validation set is 789 rows held out by problem id.

## Summary

- **Decision: decider-0.8b is not adopted.** On the validation set it scores 24.0 %
  and the baseline 22.4 %. The gain is +1.5 percentage points (pp): 12 more rows right
  out of 789, with a paired 95 % interval of −2.6 to +5.6 pp. A paired significance test
  (exact McNemar) gives p = 0.50, far from significant.
- **No run is clearly above answering one fixed letter.** For every group of problems
  we compare each run with the best score that always answering the same letter would
  get. "Clearly above" means that the run's 95 % interval lies entirely above that score.
  No run meets it.
- **Missing options from OCR (reading the options out of the problem image) show no
  sign of explaining this.** In the group where the model gets the full problem text and
  the five options, no run is clearly above that fixed-letter score either.

## Why we tried decider-0.8b

The copilot runs on an Arduino UNO Q: 4 GB of RAM, CPU only, and 60 s per problem
(the official rule, `TIME_LIMIT_SECONDS` in `config.env`). In practice that allows a
model of about 1B parameters. It answers each problem with one letter, A to E.

Jev is a closed, commercial decision model: it picks an answer in one forward pass,
without writing out its reasoning. Other authors publish open models trained to behave
like it. [Mapika/decider-0.8b](https://huggingface.co/Mapika/decider-0.8b) is one of
them.

decider-0.8b was **not** the best of these open models at math. One-pass models do not
reason step by step, and math needs that. The SO-Arena benchmark
([arXiv 2611.15777](https://arxiv.org/abs/2611.15777)) gives the highest one-pass
scores to much larger models (GLiDE, KnowLine-31B). It also shows what reasoning buys:
thinking lifts the Math score of StartLux Auto from 50.8 to 92.5.

We picked decider-0.8b because it is the open model of this kind that fits the board.
The [board constraints guide](../GUIA_RESTRICCIONES_UNOQ.html) (in Spanish) sets the
limits. It also drops into our pipeline and suits later fine-tuning:

- **Same architecture and tokenizer as the baseline.** decider-0.8b is fine-tuned from
  Qwen3.5-0.8B-Base. The baseline is the post-trained Qwen3.5-0.8B: the same network
  after its makers trained it further to follow instructions. Our pinned version of
  llama.cpp (the inference server) runs decider-0.8b once we convert it to GGUF, the
  model file format llama.cpp reads.
- **Same way of answering.** It picks the option whose letter has the highest
  probability. Our server does the same: a grammar (`root ::= [A-E]`) allows only one
  letter, and temperature 0 takes the most likely one.
- **Open.** It is Apache-2.0, and its training scripts are public.

## Hypothesis and decision rule

**Hypothesis:** decider-0.8b picks the right letter more often than the baseline, at the
same size and speed. Its model card is cautious: on multiple choice it reports scores
close to its base model.

Before the first run, the team set this rule in the experiment plan. The plan is not in
the repository. decider-0.8b counts as better only if all three conditions hold:

- It gains at least 5 pp overall.
- Exact McNemar gives p < 0.05 against the baseline.
- It loses no more than 5 pp in any language.

Otherwise the result is "no improvement shown". Board latency is out of scope.

## What we compared

The validation set has 789 rows: 281 problems, each in up to three languages
(Catalan 281 rows, English 281, Spanish 227). Three runs separate the effect of the
prompt from the effect of the weights:

| Name in this report | Run ID | Weights | Prompt | Measures |
|---|---|---|---|---|
| baseline | `laptop-baseline` | Qwen3.5-0.8B | chat | the reference |
| Qwen + decider prompt | `laptop-qwen-deciderprompt` | Qwen3.5-0.8B | decider | the prompt alone |
| decider-0.8b | `laptop-decider` | decider-0.8b | decider | the weights, with the same prompt |

The **chat** prompt is the baseline's own. The **decider** prompt is decider-0.8b's
plain layout (`Context / Question / Options / Answer: (`). The appendix has the full
setup.

**How to read the numbers:**

- Each accuracy has a 95 % Wilson interval: the range that likely holds the true rate.
- A **floor** is the score of always answering one fixed letter. Random guessing gives
  20 %. Labels are not spread evenly, so in each group one letter scores more than 20 %.
  We use the best letter, picked after seeing the labels, so the floor is a high bar.
- The **paired interval** of the gain uses the same rows answered by both runs. It is the
  range that likely holds the true gain.
- McNemar compares two runs on the same rows. It counts the rows that only one of them
  gets right.
- The three languages of one problem are not independent, so the p-values are somewhat too
  small and the intervals somewhat too narrow.

## Overall results

| Run | All rows | Catalan | English | Spanish |
|---|---|---|---|---|
| baseline | 22.4 % [19.7–25.5] | 23.1 % | 23.5 % | 20.3 % |
| decider-0.8b | 24.0 % [21.1–27.1] | 22.4 % | 26.0 % | 23.3 % |
| Qwen + decider prompt | 20.7 % [18.0–23.6] | 20.6 % | 19.2 % | 22.5 % |

Floors over all rows: random 20 %, always D 22.7 % (the best fixed letter).

## The OCR limitation

M3Kang gives the options A–E only inside the problem image. `prepare_m3kang.py` reads
them with OCR (RapidOCR). Two facts limit what the model sees:

- **A row has all five options or none.** The parser works that way by design
  (`parse_options` in `laptop/prepare_m3kang.py`): it keeps a row's options only when it
  reads all five as text. So the 309 rows without options mix OCR misses, partial reads
  that were thrown away, and options that are pictures.
- **More than half the rows need a figure** (440 of 789). A text-only model cannot see
  the figure. The dataset marks the other rows as `text_only`.

That gives four strata (groups of rows):

| | 5 options found | No options | Total |
|---|---|---|---|
| Text only | **256** | 93 | 349 |
| Needs a figure | 224 | 216 | 440 |

### The clean stratum: text only, 5 options (n = 256)

Here the prompt holds the problem text and five options. If a model can solve these
problems, it should show here. The options are not perfect, though. A separate manual
check of 15 of these rows (not in the repository) found at least one wrong option in 3
of them.

| Run | Accuracy |
|---|---|
| baseline | 19.1 % [14.8–24.4] |
| decider-0.8b | 23.0 % [18.3–28.6] |
| Qwen + decider prompt | 29.3 % [24.1–35.1] |

Floors in this stratum: random 20 %, always A 26.6 % (the best fixed letter).

**The 29.3 % is consistent with letter bias.** The letters each run answers show why:

| | A | B | C | D | E |
|---|---|---|---|---|---|
| True labels | 68 | 44 | 46 | 53 | 45 |
| baseline | 50 | 5 | 1 | 188 | 12 |
| decider-0.8b | 32 | 65 | 49 | 83 | 27 |
| Qwen + decider prompt | 240 | 5 | 1 | 8 | 2 |

- **Qwen + decider prompt answers A on 240 of 256 rows.** A is the most common true label
  here, so this fixed letter scores above 20 %. The 29.3 % stays within noise of the
  always-A floor (26.6 %).
- **The baseline answers D on 188 of 256 rows.** Its 19.1 % is close to the always-D
  score (20.7 %).
- **decider-0.8b spreads its answers across all five letters.** Its 23.0 % is below the
  always-A floor. The gap to the baseline is not significant (exact McNemar p = 0.25).

### The other strata

| Stratum | n | baseline | decider-0.8b | Qwen + decider prompt | Best fixed letter |
|---|---|---|---|---|---|
| Text only, no options | 93 | 31.2 % | 21.5 % | 15.1 % | B 32.3 % |
| Figure, 5 options | 224 | 21.9 % | 22.8 % | 16.1 % | B 26.3 % |
| Figure, no options | 216 | 23.1 % | 27.3 % | 17.6 % | D 29.6 % |

- **Text only, no options:** the baseline's 31.2 % is the highest score in the experiment,
  but always answering B gives 32.3 %. The baseline answers B on 52 of these 93 rows.
  Without options the letters mean nothing, so this is letter bias.
- **Figure, 5 options:** every run is below the best fixed letter.
- **Figure, no options:** always answering D beats all three runs.

## Statistics and decision

Exact McNemar, paired by problem id and language (n = 789):

| Comparison | Only baseline right | Only the other right | p |
|---|---|---|---|
| baseline vs decider-0.8b | 129 | 141 | 0.50 |
| baseline vs Qwen + decider prompt | 132 | 118 | 0.41 |

Change per language, decider-0.8b minus baseline: Catalan −0.7 pp, English +2.5 pp,
Spanish +3.1 pp.

| Condition | Required | Observed | Met |
|---|---|---|---|
| Overall gain | ≥ 5 pp | +1.5 pp | no |
| McNemar | p < 0.05 | p = 0.50 | no |
| Worst language | ≥ −5 pp | −0.7 pp (Catalan) | yes |

**Decision: no improvement shown.** decider-0.8b is not adopted.

## Conclusion: no sign that OCR is the bottleneck

- **Better options alone show no sign of fixing this.** In the clean stratum, where most options
  are right, no run is clearly above the best fixed letter. Neither of the two 0.8B
  models we tested shows any sign of solving these problems with a one-letter answer.
- **A fixed letter can look like a result.** The baseline leans on D and B, and
  Qwen + decider prompt on A. The label mix changes from stratum to stratum. Always
  compare a score with the best fixed letter of the same stratum.
- **No evidence that decider-0.8b changes how many rows are right.** The two models
  disagree on 270 rows (129 + 141), split almost evenly. The paired 95 % interval of the
  gain, −2.6 to +5.6 pp, is too wide to rule out a gain of 5 pp.

## Limitations

- **The control is not decider-0.8b's starting point.** decider-0.8b was fine-tuned from
  Qwen3.5-0.8B-Base. Our control uses the post-trained Qwen3.5-0.8B that the board runs.
  So the comparison answers "is decider-0.8b better than our baseline", not "what did
  Mapika's fine-tuning add". A run with Qwen3.5-0.8B-Base and the decider prompt would
  answer the second question.
- **Laptop only.** We did not measure board latency. decider-0.8b has the same size as
  the baseline.
- **decider-0.8b is English-only,** per its model card (its Hugging Face page). Here it
  also answers Catalan and Spanish.
- **We converted the decider-0.8b GGUF ourselves.** No official GGUF exists.
- **One validation split** from one shard. The strata have 93–256 rows, so their
  intervals are wide.

## Next step

Gains have to come from the pipeline:

- **A model that reasons before it answers,** within the 60 s limit. On the board, one
  line of reasoning gave 17.5 % at 26.3 s per problem
  ([`BOARD_SETUP.md`, section 11.3](../BOARD_SETUP.md#113-what-we-measured)), so this
  needs a better prompt or model.
- **Retrieval of solved examples** (`eval.py --rag K`). It works only with the chat
  prompt: the decider prompt ignores examples.
- **Better OCR,** which pays off only once the model can use the options.

The prompt is chosen with `LLM_PROMPT` in `config.env`: `chat` sends the chat prompt to

Every validation-set number in this report comes from the per-row result files of
`eval.py` (`results/eval-*-laptop-*.csv`). Those files stay out of Git under the M3Kang
data rule. `laptop/compare_runs.py`, added with this report, computes the accuracies,
intervals, floors, letter counts and McNemar tests from them, and prints aggregates only.
The paired interval of the gain follows from the McNemar counts (129 and 141 of 789) by
the Wald interval for paired proportions. The script prints the counts:

```bash
python3 laptop/compare_runs.py data/val.jsonl \
    baseline=results/eval-<time>-laptop-baseline.csv \
    decider=results/eval-<time>-laptop-decider.csv \
    qwen-dprompt=results/eval-<time>-laptop-qwen-deciderprompt.csv
```
