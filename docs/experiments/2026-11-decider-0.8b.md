# Experiment: decider-0.8b vs the Qwen3.5-0.8B baseline (laptop, 2026-11-14)

**Result: no improvement shown.** decider-0.8b scores 24.0 % against 22.4 % for the
baseline on 789 validation problems. That is +1.6 pp, with exact McNemar p = 0.50.
Every run is close to the floor of always answering D (22.7 % on this split).

## Hypothesis and decision rule

[Mapika/decider-0.8b](https://huggingface.co/Mapika/decider-0.8b) is an open clone
of a one-pass decision model, fine-tuned from Qwen3.5-0.8B-Base. It has the same
architecture and size as the baseline and picks an answer from the letter
logits, so it fits the UNO Q limits (1B parameters, 4 GB RAM, grammar `[A-E]`).

The rule below was fixed before any run. decider counts as better only if all three hold:

- it gains at least 5 pp overall;
- exact McNemar p < 0.05 against the baseline;
- it loses no more than 5 pp in any language.

Otherwise the result is "no improvement shown". Board latency is out of scope.

## Statistics and decision

Exact McNemar, paired by problem id and language (n = 789):

| Comparison | Only baseline right | Only other right | p |
|---|---|---|---|
| baseline vs decider | 129 | 141 | 0.50 |
| baseline vs qwen + decider prompt | 132 | 118 | 0.41 |

Per-language change, decider minus baseline: cat −0.7 pp, eng +2.5 pp, esp +3.1 pp.

| Condition | Required | Observed | Met |
|---|---|---|---|
| Overall gain | ≥ 5 pp | +1.6 pp | no |
| McNemar | p < 0.05 | p = 0.50 | no |
| Worst language | ≥ −5 pp | −0.7 pp (cat) | yes |

**Decision: no improvement shown.** decider-0.8b is not adopted.

## What the numbers say

- **All three runs are at chance level.** No run's interval excludes the always-D floor
  (22.7 %). On these problems a 0.8B model answering in one token does not do better than
  guessing. This matches decider's own model card, which says multiple-choice results stay
  close to the base model.
- **The control run explains the prompt effect.** With decider's prompt, plain Qwen
  answers A 95 % of the time, so the prompt alone does not help.
- **decider spreads its answers differently:** C and D instead of the baseline's A, B and D.
  This changes which problems it gets right (270 discordant pairs) but not how many.
- **The laptop baseline agrees with the board.** On English problems with options it scores
  23.2 % [17.5–30.2], close to the 22.5 % measured on the UNO Q (`docs/BOARD_SETUP.md` §11.3).

## Limitations

- **Laptop only.** No board latency was measured; decider has the same size as the baseline.
- **decider is English-only** per its model card. Here it is run on Catalan and Spanish too.
- **The decider GGUF is our own conversion.** No official GGUF exists.
- **One validation split** from one shard. The OCR found the options in the image for only
  480 of the 789 problems.

## Next step

Swapping weights at this size does not move accuracy. The gains have to come from the
pipeline instead:

- better option extraction (OCR);
- retrieval of solved examples (`--rag`);
- a model that reasons before answering, within the 60 s budget.
